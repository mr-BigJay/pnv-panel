# امکان‌سنجی تأیید خودکار بانک تجارت (Tejarat)

## خلاصه

| مسیر | مجاز / رسمی | پایداری بدون دخالت مدیر | توصیه Production |
|------|-------------|-------------------------|------------------|
| **آرک (بانکداری باز)** — [tejaratopenbanking.com](https://tejaratopenbanking.com/) | بله (قرارداد + sandbox) | بالا پس از صدور credential | **مسیر ترجیحی** برای گردش حساب (سرویس «صورت حساب به ازای هر صفحه») |
| **hb.tejaratbank.ir** (وب‌بانک خرد) | فقط UI انسانی؛ API عمومی گردش حساب منتشر نشده | پایین (OTP/MFA، تغییر UI، انقضای نشست) | فقط با **Worker فقط‌خواندن** + ورود دستی اولیه + Dry Run |
| API غیررسمی / reverse-engineering | نامشخص / پرریسک | نامشخص | **توصیه نمی‌شود** |

در بررسی از محیط Cloud Agent، بارگذاری `https://hb.tejaratbank.ir` با **504 Gateway Timeout** مواجه شد؛ بنابراین **selectorهای UI live تأیید نشده‌اند** و باید روی VPS شما پس از ورود مدیر پیکربندی شوند.

## محدودیت‌های وب‌بانک

- CAPTCHA، OTP و MFA **نباید دور زده شوند**؛ Worker فقط پس از نشست معتبر ایجادشده توسط مدیر کار می‌کند.
- هیچ کلیک/درخواست برای **انتقال وجه، پرداخت، تغییر تنظیمات یا صدور کارت** پیاده نشده است.
- اگر نشست منقضی شود، Worker وضعیت `login_required` گزارش می‌دهد و PHP **از تأیید با داده stale خودداری می‌کند** (`session_stale` / `session_login_required`).

## مسیر پیاده‌سازی در PNV

1. **فاز ۱ (فعلی):** Worker Playwright → ingest امضاشده (HMAC) → `provider=browser_worker` → `instantPayTryDepositMatch` با **Dry Run اجباری تا تأیید شما**.
2. **فاز ۲ (Production پایدار):** قرارداد آرک → `provider=arc_open_banking` (placeholder در کد؛ پس از دریافت spec sandbox تکمیل می‌شود).

## موانع «بدون دخالت مدیر»

- ورود اولیه و تجدید نشست وب‌بانک **حتماً** نیاز به مدیر دارد.
- تغییرات UI بانک ممکن است selectorها را بشکند تا به‌روزرسانی Worker.
- بدون `transaction_id` معتبر از بانک، تأیید خودکار **عمداً** انجام نمی‌شود (بررسی دستی).

## جایگزین‌های مجاز

- پیامک واریز روی اندروید + webhook داخلی (مشابه بله)، در صورت عدم قرارداد آرک.
